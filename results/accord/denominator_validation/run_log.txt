VERDICT
==============================================================================
Population-level candidate-generation selection OR (MISSING vs ENGLISH,
volume-adjusted): 0.6372 [0.5548, 0.732], p<0.001.
This fails the four-fifths rule (0.6372 < 0.80) and is a real, 
substantial upstream selection bias.

The standard per-group audit actually run in this project on the candidate
pool (exp1a) does NOT flag it on any well-powered metric: demographic-parity
gap=0.034, four-fifths ratio=0.961, FPR gap=0.024, 
precision gap=0.006 -- all comfortably inside conventional tolerance
(gap<0.05, four-fifths>0.80). The one metric that nominally moves (recall gap
=0.250) is built on 4 and 8 positive cases respectively and is not a
reliable estimate -- this project's own corrections record (C3, C12) already
states that error-rate comparisons are not estimable at this n.

CONCLUSION: NO. The standard per-group fairness audit, run the way it is
actually run in this pipeline (on the candidate pool, using well-powered
metrics), would NOT have caught the OR=0.64 candidate-generation selection
bias. This matches the synthetic sweep result in simulate.py: a per-group
audit computed on the post-selection candidate pool is structurally blind to
selection-rate disparities of this kind, because language-field completeness
predicts candidate generation but (per C11/C12) not the true underlying
clinical outcome -- i.e. the real-data case closely matches Sweep 1 of the
synthetic simulation (selection dependent on group, not on the true outcome).
