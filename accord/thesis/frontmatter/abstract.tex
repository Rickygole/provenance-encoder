  A contradiction between a nursing note and a discharge summary can carry out of the
hospital a medication instruction the care team had already stopped.
This thesis builds a standard four stage pipeline for detecting them in an
intensive care database and runs, at each stage, the control that separates real
failure from artifact. The pipeline does not work. The weak annotator's marginal runs far ahead of the confirmed
rate, fifteen to twenty-four times too often at eight billion parameters and five to six
at frontier scale, so over-calling is general and its size belongs to the labeller. But on the non-ambiguous core two models from one maker,
given one prompt and no training, separate the confirmed cases where every system
this pipeline built ranks at chance. A third model from a second maker does not, at
the same operating margin. The failure is located in the constructed pipeline,
not in the rarity, the sample size or the annotation it shares with the baseline. Three credited architectural components are audited in the code behind
their numbers: one parameter falsified as learned, one metric vacated by leakage,
one module never trained. The nulls are informative above a minimum effect the
evaluation's own class counts fix, and a pre-committed positive control shows the
training apparatus resolves a real difference on a separate task. The work does not show the task
unsolvable. It contributes a way of diagnosing a failed
pipeline and the recommendation that a one-prompt baseline be beaten first.
