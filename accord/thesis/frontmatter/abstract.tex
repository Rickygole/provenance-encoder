  A contradiction between a nursing note and a discharge summary can carry a
medication instruction out of the hospital that the care team had already stopped.
This thesis builds a standard three stage pipeline for detecting such
contradictions in an intensive care database: rule-based candidate mining, a large
language model used as a weak annotator, and a purpose-built neural detector. The
pipeline does not work. It runs the control at each stage that separates real
failure from artifact. The weak annotator's marginal runs far ahead of the
confirmed rate, on the annotated set fifteen to twenty-four times too often at
eight billion parameters and five to six at frontier scale, so over-calling is
general and its size belongs to the labeller. But on the non-ambiguous core an
off-the-shelf model given one prompt and no training separates the confirmed cases
from the rest, where every system this pipeline built ranks at chance. The failure
is located in the constructed pipeline, not in the rarity, the sample size or the
annotation that pipeline and baseline share. Three architectural components credited
with the gains are falsified by reading the code behind their numbers. A positive
control adjudicated by a rule committed beforehand shows the apparatus resolves a
real difference, so the nulls are informative above a stated minimum effect. The
work does not show the task is unsolvable. It contributes a method for turning a
failed pipeline into a diagnosed one, and the recommendation that a one-prompt
baseline be beaten first.
